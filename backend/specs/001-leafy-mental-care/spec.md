## User Scenarios & Testing *(mandatory)*

### User Story 1 - Multimodal Emotional Journaling (Priority: P1)

사용자는 텍스트, 음성 또는 이미지를 통해 자신의 하루를 기록하고, 시스템은 이를 분석하여 감정 상태를 파악한다.

**Why this priority**: 서비스의 핵심 데이터 수집 단계이며 모든 감정 분석의 기초가 됨.

**Independent Test**: 사용자가 일기를 저장했을 때, 분석 상태가 업데이트되고 감정 수치(기쁨, 슬픔, 스트레스 등)가 도출되는지 확인.

**Acceptance Scenarios**:

1. **Given** 사용자가 로그인한 상태에서, **When** 텍스트 일기를 작성하고 저장하면, **Then** 감정 점수와 요약 정보가 생성되어야 한다.
2. **Given** 일기에 음성 파일이 포함된 경우, **When** 저장 프로세스가 완료되면, **Then** 음성 데이터가 기록에 포함되고 분석이 진행되어야 한다.

---

### User Story 2 - Personalized 에이전틱 액션 (Priority: P2)

시스템은 분석된 감정 상태에 따라 사용자에게 맞춤형 활동(음악, 음식, 영화 등)을 추천하고 실행 가능한 링크를 제공한다.

**Why this priority**: 분석 결과를 바탕으로 사용자에게 실질적인 가치를 제공하고 행동 변화를 유도함.

**Independent Test**: 추천된 항목을 클릭했을 때 앱 또는 웹 브라우저를 통해 해당 컨텐츠로 연결되는지 확인.

**Acceptance Scenarios**:

1. **Given** 특정 감정(예: 우울)이 분석된 상태에서, **When** 추천 목록을 조회하면, **Then** 해당 감정에 적합한 음악/음식/영화와 딥링크가 제공되어야 한다.
2. **Given** 추천 링크를 클릭하면, **When** 외부 서비스로 이동하면, **Then** 실행 여부(is_clicked)가 기록되어야 한다.

---

### User Story 3 - 선제적 리마인더 및 고위험군 감지 (Priority: P3)

시스템은 사용자의 활동 패턴을 추적하여 장기간 미활동 시 알림을 보내거나, 지속적인 부정적 감정 감지 시 고위험군으로 분류한다.

**Why this priority**: 사용자의 지속적인 서비스 이용을 독려하고 멘탈케어의 안전망 역할을 수행함.

**Independent Test**: 24시간 미활동 시 알림이 발송되는지, 4주간의 감정 데이터가 임계치를 초과할 때 위험 플래그가 활성화되는지 확인.

**Acceptance Scenarios**:

1. **Given** 마지막 일기 작성 후 24시간이 경과하면, **When** 시스템 스케줄러가 작동하면, **Then** 사용자에게 능동형 알림이 발송되어야 한다.
2. **Given** 최근 4주간 '우울' 점수가 임계치를 초과한 경우, **When** 상태를 조회하면, **Then** 고위험군(isHighRisk)으로 표시되고 전문 상담 기관의 전화번호나 웹사이트 링크를 화면에 표시하여 안내한다.

---

### User Story 4 - Social Login via OAuth (Priority: P1)

사용자는 구글, 네이버, 카카오 계정을 사용하여 별도의 회원가입 절차 없이 시스템에 간편하게 로그인할 수 있다.

**Why this priority**: 사용자 접근성을 극대화하고 초기 가입 허들을 낮추는 필수 기능임.

**Independent Test**: 구글/네이버/카카오 로그인 버튼을 클릭했을 때 각 플랫폼의 인증 화면으로 이동하고, 인증 성공 후 시스템의 메인 화면으로 정상 진입하는지 확인.

**Acceptance Scenarios**:

1. **Given** 로그인 화면에서, **When** 구글, 네이버 또는 카카오 로그인 버튼을 선택하면, **Then** 해당 플랫폼의 OAuth 인증 프로세스가 시작되어야 한다.
2. **Given** 외부 플랫폼 인증이 완료되면, **When** 시스템으로 복귀하면, **Then** 사용자의 프로필 정보(이메일, 닉네임 등)가 자동 연동되어 계정이 생성되거나 로그인되어야 한다.

---

### Edge Cases

- 사용자가 일기를 작성하는 도중 분석 서버와의 연결이 끊기는 경우.
- 사용자의 기기에 추천 앱(예: Spotify)이 설치되어 있지 않은 경우의 처리.
- 4주간의 기록이 충분하지 않은 상태에서의 위험군 분석 로직.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 구글, 네이버, 카카오톡을 통한 OAuth 2.0 소셜 로그인을 지원해야 하며, 연동된 프로필 정보를 기반으로 사용자 계정을 관리해야 한다.
- **FR-002**: 사용자는 할 일(Todo)을 생성, 조회, 완료 처리할 수 있어야 한다.
- **FR-003**: 일기 기록은 텍스트, 음성(URL), 이미지(다중 URL) 정보를 포함하여 저장되어야 한다. 이미지는 기록용으로만 저장하며, 감정 분석 및 추천에는 텍스트와 음성 데이터만 사용한다.
- **FR-004**: 감정 분석 결과는 수치형 데이터(기쁨, 슬픔, 스트레스)와 텍스트 요약을 포함해야 한다.
- **FR-005**: 모든 추천 활동은 딥링크(URI Scheme)와 웹 Fallback URL을 동시에 제공해야 한다. 추천 카테고리는 초기 음악, 음식, 영화를 지원하며, 향후 새로운 카테고리 추가가 용이한 유연한 구조로 설계되어야 한다.
- **FR-006**: 시스템은 사용자의 구매한 아이템과 장착 정보를 관리해야 한다.
- **FR-007**: 24시간 동안 일기를 작성하지 않은 사용자에게 알림을 발송하는 로직이 포함되어야 한다.
- **FR-008**: 모든 데이터 조회 시 요청자와 데이터 소유자가 일치하는지 검증해야 한다.
- **FR-009**: 분석 작업은 사용자 응답과 독립적으로 수행되어야 한다. (비동기 처리 보장)
- **FR-010**: 사용자는 페르소나 스타일(기본형, 친구형)과 서비스 사용 목적(정신건강 관리, 단순 일기)을 설정할 수 있어야 한다.
- **FR-011**: 인증된 사용자의 식별 정보는 JWT(JSON Web Token) 형식으로 관리되어야 한다.

### Key Entities

- **User**: 사용자 계정, 프로필 및 역할 관리.
- **Journal**: 일기 본문 및 멀티모달 데이터 참조.
- **EmotionResult**: 일기에 대한 정량적 감정 점수 및 요약.
- **Recommendation**: 카테고리별 추천 컨텐츠 및 실행 링크.
- **Todo**: 사용자별 태스크 및 완료 상태.
- **Item / UserItem**: 상점 아이템 및 소유/장착 정보.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 일기 저장 후 감정 분석 결과 도출까지의 시간이 사용자 대기 시간에 영향을 주지 않아야 함.
- **SC-002**: 추천된 딥링크의 100%가 앱 미설치 시 웹 브라우저로 정상 전환되어야 함.
- **SC-003**: 24시간 미활동 알림이 조건 충족 후 10분 이이내에 발송되어야 함.
- **SC-004**: 사용자가 자신의 데이터 외에 타인의 데이터에 접근하려 할 때 모든 요청이 차단되어야 함.

## Assumptions

- 외부 AI 분석 서버는 표준화된 JSON 형식으로 감정 데이터와 추천 정보를 반환함.
- 사용자는 모바일 앱 또는 웹 환경에서 서비스를 이용하며 푸시 알림 수신이 가능함.
- 감정 분석의 '우울' 임계치 및 고위험군 분류 기준은 전문가 자문을 바탕으로 사전에 설정되며, 모든 사용자에게 공통으로 적용됨.
